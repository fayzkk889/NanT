## Start with something we can reverse

00:00 (fixture time; no source video) · Source s00001

A language model operates fundamentally on numbers, yet our initial training material arrives as text. Before constructing a model, we must establish a reversible mechanism to translate between these two representations. We will begin with a deliberately small corpus: the six-character string `ababa!`. Our objective is to convert each character into an integer and subsequently recover the exact original string from those integers. This exercise is not about predicting future text; it is purely a representation step.

We must keep three distinct quantities separate in our minds. First, the text has six specific positions. Second, it utilizes three distinct characters: `a`, `b`, and the exclamation mark. Third, each position will become one token, while the vocabulary will contain exactly one entry per distinct character. A repeated `a` must receive the same ID every time it appears. It is crucial to understand that these IDs are labels, not numerical measurements; assigning a larger number to `b` would not imply that `b` is more important than `a`.

## The first version: discover the vocabulary

01:00 (fixture time; no source video) · Source s00002

Let us begin by creating a set, which automatically removes duplicates. Converting this set into a list provides us with a vocabulary we can index. The initial implementation uses `chars.index` to find the position of each character and stores those positions in a list. This approach is sufficient to encode our tiny text.

Observe what the code on screen actually does: it searches the vocabulary again for every character, rather than preparing a lookup table once. There is also a reproducibility problem inherent in this method. We have not defined what order the vocabulary should use. Since a Python set does not promise a stable character ordering across different runs, the token IDs generated by this version cannot become a persistent file format. Do not memorize the particular IDs you happen to see; the same vocabulary ordering must be used consistently wherever we encode and decode. We will fix this ordering issue before building anything on top of these IDs.

### Version 1 · vocabulary search

```python
text = "ababa!"
chars = list(set(text))
encode = lambda s: [chars.index(c) for c in s]
ids = encode(text)
# Set ordering is not a persistent vocabulary contract.
```

## Make the mapping deterministic

02:00 (fixture time; no source video) · Source s00003

We now replace the vocabulary list with `sorted(set(text))`. For this specific corpus, the sorted list is: exclamation mark, then `a`, then `b`. Enumerating this list gives us a dictionary mapping each character to its integer ID: the exclamation mark maps to zero, `a` to one, and `b` to two. This is the mapping visible on screen.

The encoder now functions as a simple dictionary lookup for each character. Encoding `ababa!` therefore produces the sequence 1, 2, 1, 2, 1, 0 in that order. Compare this with the earlier version: the input text has not changed, and we still produce one integer per character. What has changed is how we choose the vocabulary ordering and how we perform each lookup. Sorting ensures this example is reproducible for the same character set. However, it does not make the IDs universal across different datasets; adding another character can change the sorted ordering, so a trained model's vocabulary must be saved along with its IDs.

### Version 2 · deterministic lookup

02:10 (fixture time; no source video) · e0002 · code · Authored fixture code state

```python
text = "ababa!"
chars = sorted(set(text))
stoi = {ch: i for i, ch in enumerate(chars)}
encode = lambda s: [stoi[c] for c in s]
print(chars)
print(encode(text))
```

## Build the inverse and check the round trip

03:00 (fixture time; no source video) · Source s00004

To recover text, we invert the mapping. The integer-to-string dictionary maps zero to the exclamation mark, one to `a`, and two to `b`. For each input ID, we look up its character and then join the resulting characters with an empty separator. Using a space separator would silently introduce characters that were never in the source text.

Here is the first useful invariant: `decode(encode(text))` must equal `text`. The terminal shows the encoded list followed by `ababa!`, and the assertion passes. This checks the composition of our encoder and decoder on the original example. It does not prove correctness for every possible string or ID, but it catches several common mistakes: mismatched dictionaries, reordered positions, and the wrong join separator. Keep this check beside the implementation as we change it. We now have a reversible representation for strings made entirely from the current vocabulary.

### Add the inverse mapping

03:15 (fixture time; no source video) · e0004 · code · Authored fixture code addition

```python
itos = {i: ch for ch, i in stoi.items()}
decode = lambda ids: ''.join(itos[i] for i in ids)
print(decode(encode(text)))
assert decode(encode(text)) == text
```

## Expose the boundary instead of hiding it

04:00 (fixture time; no source video) · Source s00005

Now try to encode a question mark. Our corpus never contained one, so the string-to-integer dictionary has no entry for it. The first dictionary encoder raises a `KeyError`. This is an expected boundary of the implementation, not evidence that the mapping for `ababa!` stopped working.

A tempting response might be to map an unknown character to zero. In our vocabulary, however, zero already means the exclamation mark. That would make decoding a question mark return an exclamation mark, destroying the round-trip property without telling the caller what went wrong. We will not make that substitution. For this lesson, we will reject unknown characters explicitly and report which character was missing. A production tokenizer could choose a different policy, but that policy would need a deliberately designed representation. The terminal error is part of the lesson: it explains why the next code change is necessary.

## Improve the error while preserving the contract

05:00 (fixture time; no source video) · Source s00006

Replace the small encoder expression with a named function. It still visits input characters in order and returns the same list for valid text. The difference is the boundary check: before looking up a character, we test whether it belongs to the vocabulary. If not, we raise a `ValueError` that includes the character's representation.

The terminal now shows `ValueError: unknown character: '?'` when we attempt the same unsupported input. This is a clearer message for a caller than a raw dictionary `KeyError`. We have changed the failure behavior while preserving successful encodings. Run the original round-trip assertion again after replacing `encode`. It still passes. This is why we kept an invariant close to the code: the improvement to error handling should not accidentally change IDs, skip repeated characters, or return a partially encoded result. The function either returns the complete encoding or raises an exception.

### Version 3 · an explicit failure boundary

05:10 (fixture time; no source video) · e0007 · code · Authored fixture replacement for encode

```python
def encode(s):
    ids = []
    for c in s:
        if c not in stoi:
            raise ValueError(f"unknown character: {c!r}")
        ids.append(stoi[c])
    return ids

assert decode(encode(text)) == text
```

## Read the sequence as positions, not categories

06:00 (fixture time; no source video) · Source s00007

Look at the six boxes in the diagram. The top row contains `a`, `b`, `a`, `b`, `a`, exclamation mark. The bottom row contains 1, 2, 1, 2, 1, 0. A vertical arrow joins each character to exactly one ID at the same position. The repeated `a` characters occupy three different sequence positions but share the same vocabulary ID.

This distinction matters when the sequence later becomes model input. The list preserves the order of occurrences. The vocabulary dictionary stores the identity mapping, not the whole text. A set of the token IDs would throw away both repetitions and ordering, so it could not be decoded back into the original string. We have also not added a start token, an end token, padding, or a batch dimension. The exclamation mark is ordinary data in our example; it has no special control meaning merely because its ID is zero.

### Complete runnable lesson

07:20 (fixture time; no source video) · e0010 · code · Authored fixture final state; earlier states remain above

```python
text = "ababa!"
chars = sorted(set(text))
stoi = {ch: i for i, ch in enumerate(chars)}
itos = {i: ch for ch, i in stoi.items()}

def encode(s):
    ids = []
    for c in s:
        if c not in stoi:
            raise ValueError(f"unknown character: {c!r}")
        ids.append(stoi[c])
    return ids

def decode(ids):
    return ''.join(itos[i] for i in ids)

print(chars)
print(encode(text))
print(decode(encode(text)))
assert decode(encode(text)) == text
# Run encode("?") separately to demonstrate the error.
```
